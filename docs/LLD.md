# Low-Level Design

This document is the source of truth for API contracts. The FastAPI implementation in `src/ssa_api` is validated against these definitions. An auto-generated OpenAPI spec lives at `/docs` on the running API and in `docs/openapi.yaml` (regenerated by CI).

## 1. Service endpoints — summary

| Method | Path             | Purpose                               | Auth | Response |
|--------|------------------|---------------------------------------|------|----------|
| GET    | `/health`        | Liveness probe                         | none | 200 / 503 |
| GET    | `/ready`         | Readiness probe (model reachable)      | none | 200 / 503 |
| GET    | `/metrics`       | Prometheus exposition                  | none | 200 text |
| GET    | `/model/info`    | Current model metadata                 | none | 200 JSON |
| POST   | `/predict`       | Sentiment for one ticker               | none | 200 / 400 / 503 |
| POST   | `/batch_predict` | Sentiment for many tickers             | none | 200 / 400 / 503 |
| POST   | `/feedback`      | Submit ground-truth label              | none | 202 / 400 |
| GET    | `/model/versions`| List registered versions + stages      | none | 200 JSON |
| POST   | `/model/rollback`| Rollback to a prior version            | local only | 200 / 403 / 404 |

All request/response bodies are JSON unless noted. All endpoints emit a `X-Request-ID` response header (echoed from request or generated).

## 3. `GET /health`

Liveness. Returns 200 if the API process is running. Never checks downstream.

**Response 200**
```json
{ "status": "alive" }
```

---

## 4. `GET /ready`

Readiness. Returns 200 only if the model server is reachable and reports a loaded model. Kubernetes / Swarm orchestrators use this to gate traffic.

**Response 200**
```json
{
  "status": "ready",
  "model": { "name": "stock-sentiment", "version": "7", "stage": "Production" }
}
```

**Response 503** — when model server unreachable or no model loaded
```json
{ "status": "not_ready", "reason": "model_server_unreachable" }
```

---

## 5. `GET /metrics`

Prometheus exposition format. No JSON. Includes:

- `http_request_duration_seconds` (histogram, labels: method, path, status)
- `http_requests_total` (counter)
- `predictions_total` (counter, label: sentiment)
- `model_version_info` (gauge, label: version, stage)
- `feedback_received_total` (counter, label: label)
- `feature_drift_score` (gauge, label: feature)

## 7. `POST /predict`

**Request**
```json
{
  "ticker": "AAPL",
  "lookback_hours": 24,
  "include_explanations": false
}
```

| Field                 | Type     | Required | Default | Constraints |
|-----------------------|----------|----------|---------|-------------|
| `ticker`              | string   | yes      | —       | 1–10 chars, `^[A-Z][A-Z0-9.-]*$` |
| `lookback_hours`      | integer  | no       | 24      | 1 ≤ x ≤ 168 |
| `include_explanations`| boolean  | no       | false   | — |

**Response 200**
```json
{
  "ticker": "AAPL",
  "sentiment": "positive",
  "confidence": 0.82,
  "scores": { "positive": 0.82, "neutral": 0.12, "negative": 0.06 },
  "sample_size": 147,
  "lookback_hours": 24,
  "model": { "name": "stock-sentiment", "version": "7", "stage": "Production" },
  "explanations": [
    { "source": "news", "snippet": "...", "contribution": 0.14 }
  ],
  "request_id": "uuid",
  "latency_ms": 87
}
```

The `explanations` array is present only when `include_explanations=true`.

**Response 400** — invalid ticker → `ErrorResponse` with `code="INVALID_TICKER"`.
**Response 503** — model server unreachable → `ErrorResponse` with `code="MODEL_UNAVAILABLE"`.
**Response 404** — no data in lookback window → `ErrorResponse` with `code="NO_DATA"`.

**Acceptance criteria**
- p95 latency < 200 ms for `include_explanations=false`
- Monotonic probability ordering (sum of `scores` ≈ 1.0 ± 1e-3)

## 8. `POST /batch_predict`

**Request**
```json
{
  "tickers": ["AAPL", "MSFT", "NVDA"],
  "lookback_hours": 24
}
```

| Field        | Type        | Required | Constraints |
|--------------|-------------|----------|-------------|
| `tickers`    | string list | yes      | 1–50 items, each matches ticker regex |
| `lookback_hours` | integer | no       | 1 ≤ x ≤ 168, default 24 |

**Response 200**
```json
{
  "results": [
    { "ticker": "AAPL", "sentiment": "positive", "confidence": 0.82, ... },
    { "ticker": "MSFT", "sentiment": "neutral",  "confidence": 0.61, ... }
  ],
  "model": { "name": "stock-sentiment", "version": "7", "stage": "Production" },
  "request_id": "uuid",
  "latency_ms": 213
}
```

Individual failures per ticker are represented as
```json
{ "ticker": "XYZ", "error": { "code": "NO_DATA", "message": "..." } }
```
inside the `results` array — the overall call still returns 200.

## 9. `POST /feedback`

Records ground-truth from users. Feeds the retraining pipeline and the real-world decay metric.

**Request**
```json
{
  "ticker": "AAPL",
  "prediction_request_id": "uuid",
  "true_label": "positive",
  "user_comment": "optional string"
}
```

| Field | Type | Required | Constraints |
|---|---|---|---|
| `ticker` | string | yes | ticker regex |
| `prediction_request_id` | uuid | yes | must match a prior `/predict` response |
| `true_label` | enum | yes | `positive` / `negative` / `neutral` |
| `user_comment` | string | no | ≤ 500 chars |

**Response 202**
```json
{ "accepted": true, "feedback_id": "uuid" }
```

**Response 400** — validation failure → `ErrorResponse`.

Side effects: row written to `postgres.feedback(ticker, request_id, true_label, predicted_label, received_at, user_comment)`, counter `feedback_received_total` incremented.

## 11. `POST /model/rollback`

Restricted to local-network callers (enforced by middleware checking `request.client.host`).

**Request**
```json
{ "target_version": "6" }
```

**Response 200**
```json
{
  "previous": { "version": "7", "stage": "Archived" },
  "current":  { "version": "6", "stage": "Production" },
  "reload_triggered": true
}
```

**Response 403** — non-local caller.
**Response 404** — version does not exist.
**Response 409** — version already in a non-Staging/Archived stage.

Side effect: issues a `POST /reload` to `model-server` after the stage transition.

## 13. Error handling contract

Every endpoint returns an `ErrorResponse` on non-2xx. Error codes are a closed enum (listed in §2). Every log entry includes `request_id`, `path`, `status`, `latency_ms`. Unhandled exceptions produce a 500 with `code="INTERNAL"` and a generic message — internal details are logged, never returned.

---

## 14. Versioning

The API itself versions via URL prefix starting at Phase 5: the routes above all live under `/v1`. The `X-API-Version` response header carries the build version.
